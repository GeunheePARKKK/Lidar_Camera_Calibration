# ESP32 → 라이다 인터페이스 박스 배선 정리

ESP32-S3의 3.3V 신호를 라이다 인터페이스 박스가 요구하는 5V 레벨로 변환하는 배선 문서.
- **GPS PULSE (PPS)**: 74AHCT125 버퍼로 레벨 시프트 (비반전)
- **GPS RECEIVE (NMEA)**: 2N2222 트랜지스터로 반전 + 레벨 시프트

---

## 1. GPS PULSE — 74AHCT125 레벨 시프터

### 핀 배치 (14핀 DIP, 위에서 본 그림)

```
        ┌──∪──┐
1OE  ──│1   14│── VCC
 1A  ──│2   13│── 4OE
 1Y  ──│3   12│── 4A
2OE  ──│4   11│── 4Y
 2A  ──│5   10│── 3OE
 2Y  ──│6    9│── 3A
GND  ──│7    8│── 3Y
        └─────┘
```

1번 핀 위치는 칩 한쪽 끝의 반원 홈(notch) 또는 점(dot)으로 표시됨.
4채널 버퍼이므로 8개 중 **1채널만** 사용.

### 연결표 (1번 채널)

| 74AHCT125 핀 | 연결 대상 |
|---|---|
| 14번 (VCC) | +5V |
| 7번 (GND) | GND 공통 |
| 1번 (1OE) | **GND** ← 빼먹으면 출력이 안 나옴 |
| 2번 (1A) | ESP32 GPIO5 |
| 3번 (1Y) | 인터페이스 박스 GPS PULSE (노란선) |

VCC–GND 사이에 0.1μF 세라믹 커패시터를 칩 가까이 붙이면 안정적 (없어도 대개 동작).

### 주의할 점 3가지

**① OE 핀을 반드시 GND로**
1OE는 출력 활성화 핀이며 Low일 때 활성화. 띄워두면(floating) 출력이 하이임피던스가 되어 아무 신호도 안 나감 — 74AHCT125에서 가장 흔한 실수.
안 쓰는 채널(2OE, 3OE, 4OE)은 VCC에 묶거나 그냥 둬도 되지만, 안 쓰는 입력(2A, 4A 등)은 GND에 묶는 게 깔끔함.

**② VCC는 반드시 5V**
3.3V를 주면 출력도 3.3V가 나와 승압 효과가 없음. 5V를 넣어야 3.3V 입력을 받아 5V로 올려줌 (AHCT 계열의 존재 이유).
칩에 찍힌 글자가 `74AHCT125` 또는 `74HCT125`인지 확인. `AHC125`, `HC125`라면 3.3V 입력을 HIGH로 인식 못 할 수 있음.

**③ GND 공통이 필수**
ESP32 GND, 74AHCT125 7번 핀, 인터페이스 박스 GROUND 단자가 전부 하나로 이어져 있어야 함.

### 확인 방법

- 멀티미터로 3번 핀(1Y) 전압 측정 → 1초마다 0V ↔ 5V로 튀는지 확인. PPS 폭이 20ms라 멀티미터로는 평균값이 낮게 보일 수 있으므로 오실로스코프나 LED+저항이 더 확실함.
- LED 테스트: 3번 핀 → 330Ω → LED → GND 로 물리면 1초마다 짧게 깜빡여야 함.
- 라이다 연결 후 8308 포트 status 확인 → 1(Attempting) 이상이면 PPS 경로 성공.

### 참고: 74HC125밖에 없다면

HCT가 아닌 그냥 `74HC125`는 5V VCC 기준 HIGH 인식 임계값이 약 3.5V라 ESP32의 3.3V가 애매함(동작할 수도, 안 할 수도).
그 경우 일단 그대로 시도하고, 출력이 안 나오면 VCC를 3.3V로 낮춰(승압 포기) 직결처럼 써보는 것도 방법 — 인터페이스 박스가 3.3V PPS를 받아주는 경우도 있음.

## 2. 5V 전원 (아두이노 우노 사용 시)

우노를 5V 전원으로 쓰면 **우노 GND도 반드시 공통 접지에 합류**시켜야 함. 빠지면 74AHCT125가 5V를 받아도 기준점이 없어 동작이 이상해짐.

### 왜 필요한가

전압은 항상 "어딘가에 대한 상대값". 우노가 만든 5V는 우노 GND 기준, ESP32의 3.3V는 ESP32 GND 기준이다. 두 GND가 연결되지 않으면 값을 서로 비교할 수 없어 74AHCT125가 "지금 입력이 HIGH인지 LOW인지" 판단할 기준을 잃는다. 라이다도 5V 펄스가 들어와도 무엇을 기준으로 5V인지 몰라 인식하지 못한다. GND를 이어주는 순간 모두가 같은 0V 기준을 공유하고, 그때부터 "3.3V", "5V"라는 말이 의미를 갖는다.

### 우노 사용 시 주의사항

- 우노 5V 핀에서 뽑는 전류는 74AHCT125 하나 정도(수 mA)면 전혀 문제없음. USB 전원 기준으로도 여유로움.
- 우노는 전원 공급 용도이므로 스케치를 올릴 필요 없음. USB로 전원만 들어와 있으면 5V 핀은 항상 살아 있음.
- **우노의 다른 핀은 건드리지 말 것.** 디지털 핀을 실수로 신호선에 물리면 5V가 ESP32 GPIO로 역류해 ESP32(3.3V 소자)가 손상될 수 있음.
- 전원 인가 순서는 크게 상관없으나, 안전하게 하려면 배선 완료 후 우노 USB → ESP32 USB 순으로 꽂고, 뺄 때는 반대로.

### 대안

ESP32-S3 개발보드에 5V 출력 핀(보드에 `5V` 또는 `VBUS` 표시)이 있으면 우노 없이 그것만 써도 됨. USB로 전원이 들어오면 그 핀에 5V가 나옴. (8/25 카메라 회로 문서에도 "별도 전원 모듈 없이 개발보드의 5V 출력 핀이 옵토 LED 전원을 겸한다"고 되어 있음.) GND 신경 쓸 곳이 하나 줄어 더 간단하므로 **보드에 5V 핀이 있으면 그쪽을 우선 권장**.

## 3. GPS RECEIVE — 2N2222 반전 회로

### 2N2222 핀 배치

TO-92 패키지(까만 반원통) 기준, 평평한 면을 마주보고 다리가 아래로 향하게 잡았을 때 왼쪽부터:

```
┌─────┐
│     │  ← 평평한 면(글자 있는 쪽)이 나를 향함
│     │
└─┬┬┬─┘
  │││
  EBC
  ↑↑↑
  ││└─ Collector (컬렉터)
  │└── Base (베이스)
  └─── Emitter (이미터)
```

> **주의:** 2N2222는 패키지에 따라 핀 순서가 다름. 금속캔(TO-18) 타입은 배열이 다르다. 카메라 트리거 회로에 쓴 것과 같은 부품이면 그때 확인한 순서 그대로 사용. 헷갈리면 멀티미터 다이오드 모드로 확인하거나 데이터시트 참조.

### 연결표

| 연결 | 내용 |
|---|---|
| ESP32 GPIO17 → 1kΩ 저항 → 베이스(B) | 신호 입력 |
| 이미터(E) → GND 공통 레일 | 기준점 |
| 컬렉터(C) → 인터페이스 박스 GPS RECEIVE (흰선) | 출력 |
| 컬렉터(C) → 4.7kΩ 저항 → +5V (우노 5V) | 풀업 |

컬렉터에서 선이 두 갈래로 나감 — 하나는 풀업 저항 통해 5V로, 하나는 GPS RECEIVE로.

```
                        +5V (우노)
                          │
                       [4.7kΩ]
                          │
GPIO17 ─[1kΩ]─ B ├────────┴──→ GPS RECEIVE (흰선)
                \ │
                 ╲ C
                  ╲│
                   E
                   │
                GND 공통
```

### 동작 원리

- GPIO17 **HIGH**(3.3V, idle) → 트랜지스터 ON → 컬렉터가 GND로 끌려감 → 출력 약 0.2V ≈ RS-232의 idle(마크) 쪽
- GPIO17 **LOW**(0V) → 트랜지스터 OFF → 풀업으로 올라감 → 출력 5V ≈ RS-232의 스페이스 쪽

이렇게 극성이 뒤집히면서 5V 스윙이 만들어짐. 74AHCT125로는 반전이 안 되기 때문에 트랜지스터를 사용.

## 4. 최종 배선 정리

### 5V 전원
- 우노 5V 핀 → 74AHCT125 14번 핀(VCC)
- 4.7kΩ 풀업 저항 상단

### GND 공통 레일 (브레드보드 GND 줄) — 총 5개
1. ESP32 GND
2. 아두이노 우노 GND
3. 74AHCT125 7번 핀 + 1번 핀(1OE)
4. 2N2222 이미터
5. 인터페이스 박스 GROUND 단자

브레드보드를 쓴다면 GND 레일 하나에 위 항목을 전부 꽂으면 끝. 우노는 GND 핀이 3개(디지털 헤더 2개, 전원 헤더 1개)라 아무거나 사용 가능.

### 신호
- ESP32 GPIO5 → 74AHCT125 2번 핀(1A) → 3번 핀(1Y) → GPS PULSE (노란선)
- ESP32 GPIO17 → 1kΩ → 2N2222 베이스, 컬렉터 → GPS RECEIVE (흰선)

## 5. 검증 절차

### 배선 검증 (라이다 연결 전)

- **74AHCT125 1Y (3번 핀)**: 1초마다 0V ↔ 5V. LED+330Ω으로 깜빡임 확인.
- **2N2222 컬렉터**: GPRMC 전송이 없는 대부분의 시간은 idle이므로 **0.2V 근처**로 읽혀야 함.
  - 계속 5V → 트랜지스터가 안 켜짐 (베이스 배선 / 핀 순서 확인)
  - 계속 0V → 풀업이 안 걸림 (4.7kΩ과 5V 연결 확인)
  - 1초에 한 번 GPRMC가 나갈 때 전압이 순간적으로 흔들리면 신호가 나가고 있는 것

### 최종 판정 — 8308 포트

```python
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(("", 8308))

while True:
    d, _ = s.recvfrom(1024)
    print("PPS status:", d[0xCA], "| NMEA:", d[0xCE:0xCE+72])
```

| status | 의미 |
|---|---|
| 1 (Attempting) | PPS는 들어가는데 GPRMC를 아직 못 읽음 |
| 2 (Locked) | 성공. NMEA 자리에 `$GPRMC,120000,A,3552.2840,N,...` 이 그대로 보임 |

status가 1에서 안 올라가면 이 회로로는 부족하고 진짜 음전압이 필요한 수신기라는 뜻 → **MAX3232** 주문이 답.
