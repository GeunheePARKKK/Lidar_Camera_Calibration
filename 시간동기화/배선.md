# 배선

2026-09-15 기준 최종 배선입니다. 이 상태에서 PPS `Locked`, GPRMC 정상 수신, Phase Lock 동작을 확인했습니다.

카메라 트리거(FSYNC, Line1) 회로는 [`docs/카메라_MCU_배선회로도.pdf`](docs/카메라_MCU_배선회로도.pdf)를 따릅니다. 이 문서는 라이다 쪽(PPS, GPRMC)을 다룹니다.

## 전체 연결

| 출발 | 도착 | 신호 |
|---|---|---|
| ESP32 **GPIO5** | 74AHCT125 **2번** (1A) | 1 PPS, 3.3 V |
| 74AHCT125 **3번** (1Y) | I/F박스 **GPS PULSE** | 1 PPS, 5 V |
| ESP32 **GPIO17** | MAX3232 모듈 **TXD** | GPRMC, 3.3 V TTL, 9600 8N1 |
| MAX3232 모듈 **RS-232 포트 2번** | I/F박스 **GPS RECEIVE** | GPRMC, RS-232 (평소 약 −4.8 V) |
| +5 V | 74AHCT125 **14번**, MAX3232 모듈 **VCC** | 전원 |
| ESP32 **GND** | 74AHCT125 **7번**·**1번**, MAX3232 모듈 **GND**, I/F박스 **GND** | 공통 접지 |
| ESP32 네이티브 **USB** 포트 | 노트북 | 전원 + 시리얼 (`/dev/ttyACM0`) |
| 도크 이더넷 | I/F박스 이더넷 | 라이다 데이터 (192.168.1.201 → 192.168.1.100) |

**5 V 공급원** — ESP32의 `5V` 핀(USB가 꽂혀 있을 때만 나옴, 실측 4.6~4.7 V)을 권장합니다. 우노 5V를 쓸 경우 **우노 GND도 반드시 공통 접지에 연결**해야 합니다. 5 V는 멀쩡해도 GND가 따로 놀면 칩에는 전원이 걸리지 않습니다.

**GND는 브레드보드 레일 대신 점퍼선으로 직접 연결하길 권합니다.** 이번 작업에서 GND·전원 레일 접촉 문제가 네 번 나왔습니다.

## ESP32-S3 핀

| 핀 | 용도 | 비고 |
|---|---|---|
| GPIO4 | FSYNC 10 Hz 출력 | 카메라 4대 공통 트리거 |
| GPIO5 | 1 PPS 출력 | 1초마다 20 ms HIGH (원본 펌웨어) |
| GPIO17 | GPRMC 출력 (UART1 TX) | 9600 8N1, 문장 끝 `\r\n` |
| GPIO6 / 15 / 38 / 39 | CAM1~4 Line1 입력 | 노출 확인용 |
| 5V / 3V3 / GND | 전원 | 5V는 USB 연결 시에만 |
| USB-C (`USB` 표기) | 노트북 연결 | **`UART` 표기 포트가 아님** — 그쪽은 CP2102라 로그가 안 나오고 열 때마다 리셋됨 |

## 74AHCT125 (DIP-14, 위에서 본 모습)

```
         ┌──∪──┐          ∪(홈)이나 점이 있는 쪽이 1번
 1OE  ──│1   14│── VCC  (+5 V)
  1A  ──│2   13│── 4OE
  1Y  ──│3   12│── 4A
 2OE  ──│4   11│── 4Y
  2A  ──│5   10│── 3OE
  2Y  ──│6    9│── 3A
 GND  ──│7    8│── 3Y
         └─────┘
```

- **1번(1OE)은 GND.** 액티브 LOW 인에이블이라 띄워 두면 출력이 하이임피던스가 되어 아무것도 안 나갑니다.
- 14번 ↔ 7번 사이에 100 nF를 칩 가까이.
- 안 쓰는 입력 5·9·12번은 GND에, 안 쓰는 OE 4·10·13번은 VCC에 묶습니다. CMOS 입력이 뜨면 관통 전류와 발진이 생깁니다.
- **74HC125가 아니라 74HCT/AHCT125**여야 합니다. 5 V 구동 시 74HC는 입력 HIGH 문턱이 3.5 V라 ESP32의 3.3 V를 못 넘깁니다.

## MAX3232 모듈 (TTL 4핀 + RS-232 포트)

이 모듈은 **TTL 쪽 표기가 반대**입니다. 정지 레벨 시험으로 확인했습니다.

| 핀 | 실제 역할 | 연결 |
|---|---|---|
| VCC | 전원 | +5 V (ESP32 5V) |
| GND | 접지 | ESP32 GND |
| **TXD** | **입력** (ESP32 → 모듈) | ESP32 GPIO17 |
| **RXD** | **출력** (모듈 → ESP32) | **연결 금지** — VCC 5 V일 때 5 V가 나옴 |
| RS-232 포트 2번 | RS-232 출력 | I/F박스 GPS RECEIVE |

다른 모듈로 바꾸면 핀 방향이 다를 수 있으니, 아래 정지 레벨 시험으로 먼저 확인하세요.

## 켜는 순서

1. **라이다(I/F박스) 전원을 끈 상태에서** 신호선을 배선합니다. 켜진 채로 GPS 입력선을 물리면 입력을 인식 못 한 채 남습니다.
2. ESP32를 노트북에 꽂습니다. 부팅 즉시 PPS와 GPRMC가 나갑니다.
3. 아래 측정으로 확인합니다.
4. 라이다 전원을 켭니다.
5. `python3 code/lidar_config.py --watch`로 PPS `Locked`와 NMEA 문장을 확인합니다. **ESP32 시리얼을 읽는 프로그램이 돌고 있어야 합니다** (`record.py`, 또는 트러블슈팅 12번 참고).

## 측정 체크리스트

멀티미터 DC 전압, 검은 프로브는 ESP32 GND.

| 측정 | 정상 | 아니면 |
|---|---|---|
| 74AHCT125 14번 | 4.6 ~ 5.0 V | 5 V 공급 / 레일 접촉 |
| 74AHCT125 1번 | 0 V | 출력이 하이임피던스 |
| 74AHCT125 3번 | 약 0.1 V (1초마다 살짝 흔들림) | 5 V 고정 → ESP32 시리얼이 막힌 상태 (트러블슈팅 12번) / 2.4 V 근처 → 전원이나 OE |
| MAX3232 모듈 VCC | 4.6 ~ 5.0 V | **GND 미연결을 먼저 의심** |
| I/F박스 GPS RECEIVE | **약 −4.8 V** (마이너스) | 0 V 근처 / 플러스 → 모듈 전원·GND |

PPS는 1초에 20 ms만 HIGH라서 멀티미터(DC 평균)로는 0↔5 V가 보이지 않고 약 0.1 V로 읽힙니다. 이게 정상입니다.

## 정지 레벨 시험 (핀 방향 확인)

입력을 손으로 HIGH/LOW에 고정해 출력이 따라오는지 봅니다. 펌웨어를 다시 굽지 않아도 됩니다.

| 대상 | 입력 핀을 꽂을 곳 | 출력 기대값 |
|---|---|---|
| 74AHCT125 | 2번 → ESP32 3V3 | 3번 약 5 V |
| 74AHCT125 | 2번 → ESP32 GND | 3번 0 V |
| MAX3232 모듈 | TXD → ESP32 GND | RS-232 포트 2번 **+6 V** |
| MAX3232 모듈 | TXD → ESP32 3V3 | RS-232 포트 2번 **−5 V** |

시험이 끝나면 입력 핀을 **ESP32 GPIO5 / GPIO17로 되돌립니다.**
